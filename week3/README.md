4. 平均池化文本向量的缺点：
当前模型使用字符 Embedding 的平均池化作为文本表示。该方法结构简单、计算成本低，但不保留字符顺序，因此对于字符相同但语序不同的文本，可能生成相同或非常接近的文本向量。
两句话包含的字符完全相同，只是顺序不同：
    我、投、诉、维、修、人、员
第一句话的平均向量是：
    (我 + 投 + 诉 + 维 + 修 + 人 + 员) / 7
第二句话是：
    (维 + 修 + 人 + 员 + 投 + 诉 + 我) / 7
加法顺序不会改变结果，所以两个平均向量完全相同：
    pooled_1 = pooled_2
接下来它们经过同一个 MLP，自然会得到相同的 logits 和预测结果。
也就是说，你现在的模型更像是在判断：
    这句话里出现了哪些字符？
但它不太能判断：
    这些字符按照什么顺序组成了什么意思？
